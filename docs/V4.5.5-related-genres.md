# V4.5.5: Core and related genres

Profiles keep one registered core genre in `profiles.genre`. Optional related
genre IDs are stored as JSON in `profiles.related_genres_json` (maximum five).
Existing `subgenre` values and older profiles are preserved; migrated profiles
start with an empty related-genre list.

For a new JP Morning Chill Rap profile, the dialog suggests Chill Rap, R&B
Hip-Hop, and Cafe Chill. These are editable suggestions, not forced defaults.
Existing user search terms remain first in the search plan. Built-in core terms
and optional related-genre terms are kept separate in the plan and are never
written over the user's queries. The configured call cap is hard; at budgets
of three calls or fewer, core searches take priority.

The core genre rules remain authoritative. Related signals are shown only as
reference evidence; they cannot promote a candidate to core fit. Metadata-only
uncertainty remains a request for human listening review. AI prompts explicitly
label related genres as context, and related settings participate in the AI
cache scope.

Research checkpoints capture the effective market, genres, and bounded search
plan. Active sessions block genre changes; a saved session whose settings no
longer match cannot resume, preventing mixed-setting results. Historical
candidate decisions, human labels, audits, and cached opinions are not silently
rewritten or deleted.

Offline verification does not validate actual music content or real KR/JP
precision. Google OAuth and live Gemini calls are not needed for this feature.
