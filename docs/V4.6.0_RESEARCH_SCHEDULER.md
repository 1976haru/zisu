# ZISU V4.6.0 — 다채널 장르 집중 연구 스케줄러

상태: **P0 상태 엔진과 기존 Autopilot의 Mock 가능한 호출 경계 연결 구현; 스케줄 UI·브라우저·실 API 미완료**

범위 기준: V4.5.9 기능과 데이터 보존. 기존 프로필/OAuth/SQLite/AI 체크포인트 구조를 확장하고 중복 엔진은 만들지 않는다.

현재 구현: [`mcrs/research_scheduler.py`](../mcrs/research_scheduler.py)와 `research_schedules` 테이블은 시간표·phase·일시정지/재개·복구·프로필별 체크포인트·검색 호출 예약 상태를 제공합니다. `run_autopilot_block`은 기존 Autopilot 세션·검색 및 AI 예산을 재사용하고, 검색 호출을 일정 phase에 맞춰 예약합니다. 연구 구간이 끝나면 새 요청을 막고 같은 세션 체크포인트를 보존합니다. 실제 외부 API는 호출하지 않았습니다. 저부하 정책은 [`mcrs/resource_guard.py`](../mcrs/resource_guard.py)에 있으며 CPU/RAM 상태를 10초보다 자주 샘플하지 않도록 하고 새 검색·AI 판정만 보류합니다. 스케줄 UI, 전용 브라우저 종료/재사용, 자원 회복 자동 재개, 장시간 Windows 계측은 아직 구현·검증 대상입니다.

## 목표

여러 Google 계정과 YouTube 채널을 프로필별로 분리 관리하면서, 사용자가 정한 시간 범위 안에서 장르 후보를 조사·정리한다. 긴 세션은 연구 시간과 휴식 시간으로 구분한다. 이 기능은 연구 보조이며 시청시간이나 채널 성과를 인위적으로 만들지 않는다.

## 우선순위와 인수 조건

### P0 — 일정·세션 엔진과 데이터 안전

- 총 예약 길이: 2/4/6/8시간. 연구 구간: 20/30/40분. 휴식 구간: 15/30/40분. 시작 시각과 프로필·시장·장르를 세션 생성 시 고정한다.
- 연구/휴식 구간 전환과 남은 시간을 표시한다. 앱 종료·VPN/네트워크 단절·API 할당량 초과 시 안전하게 일시 정지하고, 세션 ID·프로필 ID·구간 커서·사용량·처리한 영상 ID를 체크포인트로 복구한다.
- 예약 세션은 저장된 승인 한도 안에서만 읽기 전용 YouTube 검색을 사용한다. 할당량 부족이나 인증/연결 오류가 나면 무한 재시도하지 않고 예외 대기 상태로 둔다. VPN/IP 회전과 제한 우회는 금지한다.
- 핵심 장르를 우선하고 선택된 유사 장르를 보완 검색한다. 이미 수집·사람 검토한 video ID를 제거하고, 최근 같은 채널에 편중되지 않도록 후보 선택 다양성을 기록한다. 무작위성은 후보 다양성 목적에만 쓴다.
- 규칙 판정, AI 의견, 사람 청취 판정을 분리한다. 장르 근거/불확실성은 별도로 보여 주며 근거가 모자라면 사람 검토 대기함으로 보낸다.
- Mock 시계로 6시간 작업을 가속 시뮬레이션해 연구/휴식 전환, 예산 경계, 중단·재개, 중복 요청 방지, 프로필 격리를 검증한다. 실제 외부 계정/API 호출이나 참여 지표는 발생시키지 않는다.
- 저부하 기본 정책: 시스템 CPU 80% 이상이 60초 지속되면 새 검색/AI 작업을 보류하고, 사용 가능 RAM 2 GiB 미만 또는 시스템 메모리 90% 이상이면 새 무거운 작업/브라우저 시작을 막는다. 진행 중인 요청은 안전하게 마친 뒤 체크포인트를 남긴다. ZISU는 다른 사용자 프로그램을 종료하거나 메모리를 강제 회수하지 않는다. 임계값은 코드 설정 객체에서 조정 가능하며, GUI 사용자 설정 저장은 미완료다.

### P1 — 초보자용 연구 화면과 수동 영상 검토

- 기본 화면은 항상 다음에 해야 할 행동 하나를 크게 제시한다. 대표 흐름: `[연구 시간 설정]` → `[유사 장르 찾기]` → `[새 창에서 영상 열기]` → `[감상 메모하기]` → `[다음 후보 보기]` → `[잠시 쉬기]` → `[이전 작업 이어하기]` → `[오늘의 연구 결과 보기]`.
- 세션 설정에는 전체 시간, 연구/휴식 간격, 시작 시각, 프로필/채널, 국가, 핵심/유사 장르를 포함한다. 진행 중에는 현재 구간, 남은 시간, 실제 검색 호출 수와 잔여 승인 한도, 후보/중복/검토 수를 구분해 표시한다.
- 선택한 영상은 기본 브라우저 또는 사용자가 지정한 브라우저로 열 수 있다. 새 창 실행은 운영체제/브라우저가 허용하는 경우 요청하되, 쿠키 추출·자동 로그인·계정 전환은 하지 않는다. 영상 재생은 사용자가 직접 시작한다.
- 현재 작업 프로필, 연결된 Google 계정 이메일(가능한 경우), YouTube 채널 ID/이름을 명시하고 후보를 열기 전에도 작업 컨텍스트를 확인할 수 있게 한다. 브라우저 로그인 상태가 프로필 계정과 다를 수 있음을 안내한다.
- 감상 메모는 사용자가 직접 입력한다. 댓글은 기존 채널별 라이브러리를 재사용해 초안을 제안하되 실제 감상 메모가 없으면 구체적인 청취 경험을 꾸며내지 않는다. 유사 문장 및 과도한 자기 채널 홍보를 경고하고 사용자가 편집·복사·게시를 직접 수행한다.
- 휴식 중에는 자동 재생 대신 휴식 안내, 기존 후보 정렬, 승인된 AI 메타데이터 분석, 보고서 정리를 제공한다.

### P2 — 검증 가능한 성과 보고

- 조사 활동량: 후보 수, 사람이 실제 확인한 영상 수, 메모 수, 보류 수 및 장르별 사람 정답 기준 정확도를 기록한다.
- 채널 성과: 제목/썸네일 개선 제안과 실제 노출·CTR·시청시간 변화를 활동량과 분리한다. 후자는 사용자가 승인하고 필요한 읽기 전용 YouTube Analytics 권한을 설정한 경우에만 표시한다.
- YouTube 추천 알고리즘 내부 지수나 검증할 수 없는 가짜 성장 점수를 산출하지 않는다. 제안과 관측 데이터를 명확히 구분한다.

## 절대 제한

- 자동 재생, 반복 재생, 무인 시청, 시청시간/조회수 인위적 생성, 자동 좋아요·구독, 자동 또는 대량 댓글, 다계정 참여 조작, 탐지 회피, IP/VPN 회전은 구현하지 않는다.
- API 요청은 읽기 전용으로 제한한다. 계정별 OAuth, 채널 ID, 후보·메모·댓글 초안·사람 라벨·예산·체크포인트는 서로 격리한다.
- 오류·일시정지·복구 시 외부 요청의 처리 여부가 불확실하면 자동 재호출하지 않고 상태를 확인하도록 대기한다.

## 테스트 계획

- Fake clock 기반 6시간 전체 세션과 연구↔휴식 경계, 사용자가 정한 시작 시각.
- 가상 CPU 연속 부하, RAM 부족, ZISU 메모리 증가, API 진행 중 부하 변화, 재개 후 예산 불변성.
- 다중 계정/채널/프로필 전환과 메모·후보·예산·세션 격리.
- 검색 중복·채널 편중 완화·핵심 장르 우선·유사 장르 참고 처리.
- 검색 할당량 및 AI 비용 한도, 401/403/429/네트워크 단절의 안전 정지와 재개.
- 앱 강제 종료 후 체크포인트 복구, 동일 세션/페이지 중복 요청 방지.
- 브라우저 새 창 요청은 로컬 Mock 핸들러로만 검증하고 외부 영상 페이지는 호출하지 않는다.
- 댓글 초안의 메모 출처, 반복 문장 및 자기 홍보 경고, 자동 게시 코드/행위 부재.
- 성과 보고의 조사 활동량과 실제 Analytics 지표 구분 및 출처 표시.
- 초보자 작업 화면의 키보드 조작, 고배율 레이아웃, 예외 안내, Windows GUI/onedir 회귀.
