# ADR-004: V4.5 AI Research Manager

Status: accepted for implementation, 2026-10-17

## Context

ZISU already has a conservative KR/JP genre rules engine, profile-scoped SQLite
data, and a read-only YouTube lookup path. V4.5 adds assistance without
delegating account actions, approvals, or arbitrary tool execution to a model.
The default installation must remain useful without credentials or a model.

## Options

1. Adopt an autonomous agent framework with tools and handoffs. Rejected: adds
   weight and an unnecessary execution surface to a small Tkinter desktop app.
2. Deterministic workflow manager plus typed provider protocol and explicit
   read-only HTTP adapters. Selected: no required SDK; clear call boundaries;
   models can only advise on bounded metadata.
3. Provider-specific SDKs in the core app. Rejected: multiple dependency trees
   would increase EXE size and introduce provider calls at import time.

## Decisions and guardrails

- Existing rules run first. AI is called only for `검토`; `제외` is immutable,
  and an AI `적합` opinion cannot auto-approve a `검토` item.
- All displayed model opinions have provenance, metadata-only warning,
  uncertainty and a human listening recommendation. The human label remains
  the source of approval.
- Mock Demo uses fictional fixtures, performs no network/OAuth/API calls and
  writes no candidate, AI cache, or user DB data.
- Optional Ollama/OpenAI/Gemini adapters use bounded timeouts, bounded response
  bodies, structured output checks, and allowlisted error codes. OpenAI/Gemini
  keys are stored as current-user Windows DPAPI ciphertext outside the repo;
  Google OAuth token storage remains separate and unchanged.
- Paid remote calls default to OFF. An explicit per-run confirmation plus a
  user-entered conservative per-call estimate and daily USD ceiling are required;
  the app does not assume vendor prices or free quotas. Requests are capped at
  10/provider/job and 30/provider/profile/day. Cached opinions create no call.
  AI usage and YouTube search quotas remain separate accounting domains.
- Only title and bounded description are sent to a provider after explicit
  provider integration. Never send account email, profile ID, OAuth token,
  private notes or user labels. YouTube content is untrusted data; no tools are
  exposed to a model.
- AI review cache is an additive SQLite table, isolated by profile, video,
  metadata hash, genre, provider, model and prompt version. It never overwrites
  human labels or candidate decisions.
- AI usage and long research checkpoints are additional profile-scoped SQLite
  tables. Session state records market, genre, target, query index, candidate
  IDs/data and whether a read-only request may have been in flight. An
  indeterminate request is retried only for that query and candidate IDs are
  deduplicated; the UI warns this can consume another YouTube quota unit.
- Human review, direct listening, and final comment publishing remain manual.
  No automated engagement or media download is added.

## Validation required

Automated Mock and HTTP-fixture tests, current full unit/stress gates, GUI smoke,
Windows onedir artifact smoke, then separate user acceptance for real provider
keys, OAuth/API research, human-labeled real audio quality and Python-free PC.

## Deferred

Actual provider connections, Google OAuth, real-video genre labels, locale-
quality review of generated Japanese drafts, and Python-free independent PC
acceptance remain deferred. No AI comment drafting is exposed in this slice.

## Provider protocol references checked for this implementation

- Gemini `generateContent` model-specific structured output: Gemini 2.5 uses
  `generationConfig.responseMimeType: "application/json"` with
  `responseJsonSchema`; Gemini 3 uses `responseFormat.text.mimeType` with the
  `APPLICATION_JSON` enum. Unknown model contracts fail before dispatch.
  Official references: https://ai.google.dev/api/generate-content and
  https://ai.google.dev/gemini-api/docs/generate-content/structured-output
- Gemini Developers Forum clarification (2026-10-16) for the raw REST enum
  conflict and supported `responseMimeType` + `responseJsonSchema` alternative:
  https://discuss.ai.google.dev/t/generatecontent-structured-json-mime-contract-conflict-and-bare-http400/188396
- Gemini HTTP error code and quota semantics:
  https://ai.google.dev/gemini-api/docs/generate-content/api-errors
- OpenAI Chat Completions `response_format` JSON Schema:
  https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create
- OpenAI secret handling guidance:
  https://developers.openai.com/api/reference/overview
- Ollama local `/api/generate`, JSON response mode:
  https://github.com/ollama/ollama/blob/main/docs/api.md

## V4.5.2 compatibility and cost validation

- The `gemini-2.5-flash` default contract is covered by an HTTP adapter fixture;
  Gemini 3 enum formatting is independently fixture-tested. Provider 400,
  401/403, 429 and 5xx responses remain sanitized and cannot promote a review
  candidate or alter a human label.
- User-entered cost estimates are finite, positive preflight controls, not a
  guarantee of the provider's billed amount. NaN, infinities, zero, negative,
  malformed and estimate-above-ceiling values fail closed. Reservations remain
  profile-scoped and atomic under concurrent calls.

## V4.5.3 one-call Gemini connection check

- The optional UI action requires an explicit confirmation and a valid user-entered
  estimate/ceiling. It reads the Gemini credential only from the current Windows
  user's DPAPI store and always fixes the model to `gemini-2.5-flash`.
- The check sends a single hard-coded Japanese metadata fixture, does not call
  YouTube/OAuth, and writes its request reservation/profile only to a short-lived
  isolated SQLite database. There is no retry path; the final verdict is always
  `검토`, regardless of the AI opinion. Error bodies and raw outputs are discarded.
- Mock HTTP tests verify success, Unicode, malformed JSON, authorization, request
  format, quota, server, model-unavailable, no-key, budget, cancellation, one-call
  behavior, and unchanged user DB state. No actual API key or external call is used
  by automated tests.
